Before you start

A StackHub, an ASB/MCP host computer with desktop Chrome, Edge or Chromium, a USB data cable, a 2.4 GHz uplink with internet access, and a Chan/Xiaozhi MCP WSS endpoint. StackHub uses the uplink for WSS; the computer browser accesses the backend.

Step by step

  1. Join the stackhub hotspot (initial password build.me). Open http://192.168.78.1/ manually and sign in with the initial admin password build.me. Saved or changed credentials take precedence.
  2. Configure the 2.4 GHz uplink. In the Chan/Xiaozhi field, paste the complete wss:// MCP endpoint, including its token. This is separate from the backend MCP URL.
  3. Configure one backend: paste its full HTTP/HTTPS MCP URL, including required query parameters, or paste standard mcpServers JSON with url and optional headers. If several entries exist, select one. Validate and save; format validation does not prove connectivity.
  4. On the ASB computer, run tools/install_host.py from the StackHub project once, supplying --asb-root with the actual ASB directory. Then open http://127.0.0.1:8800/static/pico-gateway/index.html (adjust the ASB port if needed).
  5. Connect StackHub by USB. In the bridge page, enter the device admin password, keep Use device configuration selected, click Connect USB and choose the board. Keep this page open; closing it stops the bridge.
  6. Check Wi-Fi, MCP/WSS, USB, Bridge and backend status separately. Ask Chan to search for a tool, inspect its schema, then call a harmless status/query tool. A WSS connection alone does not prove the full path works.
  7. In Advanced settings, Change device password updates the Wi-Fi/admin password. The admin change is immediate; apply the new Wi-Fi password after a power cycle and reconnect the bridge.

Backend JSON example — replace URL and authentication with your service’s values.

{
  "mcpServers": {
    "local": {
      "url": "http://127.0.0.1:8800/mcp-http",
      "headers": {
        "Authorization": "YOUR_SERVICE_AUTH_VALUE"
      }
    }
  }
}
python tools/install_host.py --asb-root "PATH_TO_ASB"

https://YOUR_MCP_HOST/mcp-http?asb_service_api_key=YOUR_URL_ENCODED_KEY

Compatibility & limits

The computer browser, not the board, calls the backend. Local 127.0.0.1 refers to that computer. A local ASB backend does not require the computer to join the hub hotspot; a remote backend must be reachable from the computer and allow browser CORS. No stdio process launching, OAuth login, legacy SSE or multi-backend aggregation. One request at a time; large results are limited by firmware. Use search → schema → call instead of exporting the entire catalog. Category availability depends on the installed firmware and backend. Keep real tokens private. Chan end-to-end compatibility must be checked with the installed firmware.

开始前准备

准备 StackHub、运行 ASB／MCP 的电脑、桌面 Chrome／Edge／Chromium、USB 数据线、可上网的 2.4 GHz Wi-Fi，以及 Chan／小智提供的 MCP WSS 地址。WSS 由 StackHub 上联；后端 MCP 由电脑浏览器访问。

操作步骤

  1. 连接 stackhub 热点，初始密码 build.me。手动打开 http://192.168.78.1/，管理页初始密码也是 build.me。已经修改或保存的密码优先。
  2. 配置 2.4 GHz 上联 Wi-Fi。在 Chan／小智 MCP 一栏粘贴完整 wss:// 地址，包括其 token。这个地址和后端 MCP 地址是两个不同配置。
  3. 配置一个后端：可以粘贴带完整路径及必要查询参数的 HTTP／HTTPS MCP URL；也可以粘贴含 url、可选 headers 的标准 mcpServers JSON。多个条目需明确选一个。验证并保存；格式通过不代表连接成功。
  4. 在 ASB 电脑上，从 StackHub 项目运行 tools/install_host.py 一次，用 --asb-root 指定实际 ASB 目录。然后打开 http://127.0.0.1:8800/static/pico-gateway/index.html；端口以你的 ASB 为准。
  5. 用 USB 连接 StackHub。在桥接网页输入设备管理密码，保持“使用设备配置”，点击“连接 USB”并选择板子。必须保持此页打开，关闭网页会停止桥接。
  6. 分别检查 Wi-Fi、MCP／WSS、USB、Bridge 和后端状态。让 Chan 先搜索工具、查询参数，再调用无副作用的状态／查询工具。只显示 WSS 已连接不能证明全链路成功。
  7. 高级设置中的“修改设备密码”同时更新 Wi-Fi 与管理密码。管理密码立即生效，热点密码重启后应用；随后重新连接 USB 桥接。

后端 JSON 示例：将地址和认证替换为你的服务实际值。

{
  "mcpServers": {
    "local": {
      "url": "http://127.0.0.1:8800/mcp-http",
      "headers": {
        "Authorization": "YOUR_SERVICE_AUTH_VALUE"
      }
    }
  }
}

兼容性与限制

后端请求由电脑浏览器执行，不是板子直连；127.0.0.1 指 USB 所连电脑。本地 ASB 不要求电脑接入 Hub 热点；远端服务须能从电脑访问，并允许浏览器跨域。当前不支持 stdio 启动进程、OAuth 登录、旧式 SSE 或多后端聚合。一次一个请求，大结果受固件消息上限限制。优先搜索 → 获取参数 → 调用，避免把全部工具目录塞给 Chan；分类能力以所装固件和后端为准。不要公开真实 token。完整 Chan 链路须以所装固件实测为准。

準備するもの

StackHub、ASB/MCP パソコン、Chrome/Edge/Chromium、USB データケーブル、インターネット接続のある2.4 GHz Wi-Fi、Chan/小智のWSSエンドポイントが必要です。

操作手順

  1. stackhub に接続（初期パスワード build.me）。http://192.168.78.1/ を手動で開き、管理パスワード build.me でログイン。変更済みなら新しい値を使います。
  2. 2.4 GHz の上位Wi-Fiを設定し、Chan欄にトークンを含む完全な wss:// MCPアドレスを入力。バックエンドURLとは別です。
  3. バックエンドの完全なHTTP/HTTPS URL、またはurlと任意のheadersを持つmcpServers JSONを入力。複数ある場合は1つ選択し、検証・保存。形式検証は接続確認ではありません。
  4. ASBパソコンでStackHubプロジェクトの tools/install_host.py を一度実行し、--asb-rootにASBフォルダーを指定。http://127.0.0.1:8800/static/pico-gateway/index.html を開きます。
  5. USB接続後、ブリッジページで管理パスワードとUse device configurationを選び、Connect USBで機器を選択。ページを閉じると停止します。
  6. Wi-Fi、WSS、USB、Bridge、バックエンドを個別に確認。Chanで検索→スキーマ取得→安全な状態照会を試します。
  7. AdvancedのChange device passwordでWi-Fiと管理パスワードを変更。Wi-Fiは電源再投入後に適用し、USBも再接続。

バックエンドJSON例：URLと認証値を置き換えてください。

{
  "mcpServers": {
    "local": {
      "url": "http://127.0.0.1:8800/mcp-http",
      "headers": {
        "Authorization": "YOUR_SERVICE_AUTH_VALUE"
      }
    }
  }
}

互換性と制限

バックエンドはパソコンのブラウザーが呼び出します。127.0.0.1はそのパソコンです。リモートサービスには到達性とCORSが必要。stdio、OAuth、旧SSE、複数バックエンド集約は非対応。1要求ずつ、結果サイズは固件依存。全ツールを渡さず検索→スキーマ→呼出し。カテゴリは固件とサービスに依存。トークンは非公開に。Chan全経路は実機で確認してください。

Vorbereitung

StackHub, ASB/MCP-Computer mit Chrome/Edge/Chromium, USB-Datenkabel, 2,4-GHz-WLAN mit Internet und Chan/Xiaozhi-WSS-Endpunkt.

Schritt für Schritt

  1. Mit stackhub verbinden, initiales WLAN- und Admin-Passwort build.me. http://192.168.78.1/ manuell öffnen. Geänderte Zugangsdaten haben Vorrang.
  2. 2,4-GHz-Uplink und vollständigen wss://-Endpunkt einschließlich Token im Chan-Feld eintragen. Dieser ist vom Backend getrennt.
  3. Eine HTTP/HTTPS-Backend-URL mit nötigen Parametern oder mcpServers-JSON mit url und optionalen headers eintragen. Einen Server wählen, validieren, speichern. Formatprüfung ist kein Verbindungstest.
  4. Auf dem ASB-Computer tools/install_host.py aus dem StackHub-Projekt mit --asb-root und dem ASB-Verzeichnis ausführen. http://127.0.0.1:8800/static/pico-gateway/index.html öffnen.
  5. USB anschließen. Admin-Passwort eingeben, Use device configuration behalten, Connect USB wählen. Die Brückenseite muss geöffnet bleiben.
  6. WLAN, WSS, USB, Bridge und Backend getrennt prüfen. Chan: Werkzeug suchen, Schema abrufen, harmlose Statusabfrage aufrufen.
  7. Change device password ändert WLAN und Admin-Zugang. WLAN wird nach Neustart wirksam; USB-Brücke neu verbinden.

Backend-JSON: URL und Authentifizierung durch eigene Werte ersetzen.

{
  "mcpServers": {
    "local": {
      "url": "http://127.0.0.1:8800/mcp-http",
      "headers": {
        "Authorization": "YOUR_SERVICE_AUTH_VALUE"
      }
    }
  }
}
python tools/install_host.py --asb-root "PATH_TO_ASB"

https://YOUR_MCP_HOST/mcp-http?asb_service_api_key=YOUR_URL_ENCODED_KEY

Kompatibilität und Grenzen

Das Backend wird vom Computerbrowser angesprochen. 127.0.0.1 bezeichnet diesen Computer. Remote-Dienste müssen erreichbar sein und CORS erlauben. Kein stdio, OAuth, altes SSE oder mehrere Backends gleichzeitig. Eine Anfrage gleichzeitig; Ergebnisgröße firmwareabhängig. Suchen → Schema → Aufrufen statt Gesamtkatalog. Kategorien hängen von Firmware und Backend ab. Tokens geheim halten. Chan-Ende-zu-Ende-Verbindung am Gerät prüfen.

Préparation

StackHub, PC ASB/MCP avec Chrome/Edge/Chromium, câble USB, Wi-Fi 2,4 GHz avec Internet et adresse WSS Chan/Xiaozhi.

Étapes

  1. Rejoignez stackhub ; mots de passe Wi-Fi et admin initiaux : build.me. Ouvrez http://192.168.78.1/. Utilisez vos nouveaux identifiants si vous les avez changés.

  7. Change device password modifie Wi-Fi et admin. Le Wi-Fi applique le changement après redémarrage ; reconnectez le pont USB.

{
  "mcpServers": {

Compatibilité et limites

자세히모든 제품

준비

StackHub, Chrome/Edge/Chromium을 갖춘 ASB/MCP 컴퓨터, USB 데이터 케이블, 인터넷 가능한 2.4 GHz Wi-Fi, Chan/Xiaozhi WSS 주소가 필요합니다.

사용 순서

  1. stackhub에 연결합니다. 초기 Wi-Fi·관리 암호는 build.me입니다. http://192.168.78.1/을 직접 여세요. 변경한 암호가 있으면 그 값을 사용합니다.
  2. 2.4 GHz 상위 Wi-Fi와 토큰을 포함한 전체 wss:// 주소를 Chan 필드에 입력합니다. 백엔드 주소와 별개입니다.
  3. 전체 HTTP/HTTPS MCP URL 또는 url 및 선택적 headers를 포함한 mcpServers JSON을 입력합니다. 하나를 선택해 검증·저장합니다. 형식 검증은 연결 성공을 의미하지 않습니다.
  4. ASB 컴퓨터에서 StackHub 프로젝트의 tools/install_host.py를 --asb-root와 ASB 폴더로 실행합니다. http://127.0.0.1:8800/static/pico-gateway/index.html을 엽니다.
  5. USB 연결 후 관리 암호를 입력하고 Use device configuration을 유지한 채 Connect USB를 누릅니다. 페이지를 닫으면 브리지가 중지됩니다.
  6. Wi-Fi, WSS, USB, Bridge, 백엔드를 각각 확인합니다. Chan에서 검색→스키마 확인→안전한 상태 조회를 실행합니다.
  7. Change device password로 Wi-Fi와 관리 암호를 변경합니다. Wi-Fi는 재부팅 후 적용되며 USB 브리지도 다시 연결하세요.

백엔드 JSON 예: 주소와 인증을 실제 값으로 바꾸세요.

{
  "mcpServers": {
    "local": {
      "url": "http://127.0.0.1:8800/mcp-http",
      "headers": {
        "Authorization": "YOUR_SERVICE_AUTH_VALUE"
      }
    }
  }
}
python tools/install_host.py --asb-root "PATH_TO_ASB"

호환성과 제한

컴퓨터 브라우저가 백엔드를 호출합니다. 127.0.0.1은 해당 컴퓨터입니다. 원격 서비스에는 접근성과 CORS가 필요합니다. stdio, OAuth, 구형 SSE, 다중 백엔드 통합은 미지원입니다. 한 번에 한 요청, 결과 크기는 펌웨어 제한을 받습니다. 전체 도구 대신 검색→스키마→호출을 사용하세요. 분류 기능은 펌웨어와 서비스에 따라 다릅니다. 토큰을 공개하지 마세요. Chan 전체 경로는 실기 검증이 필요합니다.

التحضير

تحتاج StackHub وحاسوب ASB/MCP بمتصفح Chrome/Edge/Chromium وكابل بيانات USB وشبكة 2.4 GHz بالإنترنت وعنوان WSS من Chan/Xiaozhi.

خطوات الاستخدام

  1. اتصل بـstackhub. كلمة Wi-Fi والإدارة الأولية build.me. افتح http://192.168.78.1/ يدوياً. استخدم القيم المعدلة إن غيّرتها.
  2. اضبط شبكة 2.4 GHz وأدخل عنوان wss:// كاملاً مع الرمز في حقل Chan. يختلف عن عنوان الخدمة الخلفية.
  3. أدخل URL كاملاً لـHTTP/HTTPS MCP أو JSON من نوع mcpServers مع url وheaders اختيارية. اختر خدمة واحدة وتحقق واحفظ. صحة التنسيق لا تثبت الاتصال.
  4. شغّل tools/install_host.py من مشروع StackHub على حاسوب ASB مع --asb-root ومجلد ASB. افتح http://127.0.0.1:8800/static/pico-gateway/index.html.
  5. صِل USB وأدخل كلمة الإدارة واترك Use device configuration ثم اختر Connect USB. إغلاق الصفحة يوقف الجسر.
  6. تحقق من Wi-Fi وWSS وUSB وBridge والخدمة كل على حدة. اطلب من Chan البحث ثم المخطط ثم استعلام حالة دون آثار جانبية.
  7. يغيّر Change device password كلمتي Wi-Fi والإدارة. تطبّق Wi-Fi بعد إعادة التشغيل؛ أعد توصيل جسر USB.

التوافق والحدود

متصفح الحاسوب هو من يستدعي الخدمة، و127.0.0.1 يعني ذلك الحاسوب. تحتاج الخدمة البعيدة إلى قابلية الوصول وCORS. لا دعم لـstdio أو OAuth أو SSE القديم أو تجميع عدة خدمات. طلب واحد في كل مرة وحدود الحجم حسب البرنامج الثابت. استخدم البحث ثم المخطط ثم الاستدعاء بدلاً من الكتالوج الكامل. التصنيفات حسب البرنامج والخدمة. لا تنشر الرموز. تحقق من مسار Chan الكامل على الجهاز.
